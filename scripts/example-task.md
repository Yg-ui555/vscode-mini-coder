# 示例任务书：用 Mini-Coder 在真实项目上做一次受控改造

> 这是一份**任务书示例**，展示怎么给 `npm run audit -- <路径> --task <本文件>` 下达指令。
> 任务书里的内容会原样作为 user message 发给 agent。
>
> 写法要点（三条，缺一条就容易翻车）：
> 1. **精确到文件行号** —— 说清楚改哪几处，别让 agent 自己找
> 2. **禁改清单** —— 明确划出碰了就算错的区域
> 3. **验收标准 + 已知的既有失败** —— 让 agent 自己判断有没有引入回归

---

## 任务：代码质量改造（4 项，全部为机械改动，不涉及业务逻辑）

⚠️ **只做下面明确列出的改动。不要做任何其他改动。**
不要重构、不要格式化整文件、不要「顺手优化」、不要改 import 顺序、不要加新功能。
**每一处 diff 都必须能对应到下面某一条。**

改文件用 `apply_patch`（不要 `write_file` 整文件覆盖）；
`run_shell` 只用来跑验证命令。

---

## 改动 1：把散落在多处的魔法数字提成公共常量

**现状**：数值 `X` / `Y` 硬编码在 5 个地方（把真实的文件:行号列出来）。

**要做**：
1. 新建 `src/xxx/config.py`，定义 `X_VALUE = X` / `Y_VALUE = Y`
   —— ⚠️ 这个文件**只放常量，不 import 任何东西**（避免循环 import）
2. 主源头（类默认值）改成引用常量
3. 其余调用点改成引用常量，各自加 import

**注意**：
- 数值**绝对不能变**
- 无参调用（自动跟随默认值）的地方**保持原样**
- 文档里的文字描述不用改

---

## 改动 2：删除重复赋值

**现状**：同一个函数里 `x = ...` 在 `:A` 和 `:B` 各算了一遍，`:B` 是多余的。

**要做**：删掉 **`:B`**，保留 `:A`。

⚠️ **注意**：`:A` 可能在中间被用了，**别删错行**。

---

## 改动 3：硬编码地址改读环境变量

**现状**：代码里写死了 `http://127.0.0.1:PORT`，而 `.env.example` 已经定义了对应的环境变量。

**要做**：`os.getenv("XXX_BASE_URL", "http://127.0.0.1:PORT")`

**注意**：
- 默认值保持原样 → 当前 `.env` 里没配这个变量，**运行时行为完全不变**
- 只改这一处，其他文件里同样的地址**不在本次范围**

---

## 改动 4：给静默吞异常补日志

**原则**：**只加一行日志**。不改 return 值、不改 except 条件、不加 try/except。

**清单**：
1. `src/a.py` —— 读失败静默返回默认值
2. `src/b.py` —— 写失败静默 `return False`
3. `src/c.py` —— `except Exception: pass`

**注意**：
- **logger 名字要跟该文件已有写法一致**（有的文件用 `log`，有的用 `logger`，自己看）
- 级别用 `warning`
- **不要打印密钥、密码、用户隐私内容**

---

## 🚫 禁改清单（碰了就算你做错了）

- 任何合规 / 权限 / 安全过滤相关逻辑
- 数据库 SQL 与迁移脚本
- LLM 的 prompt 模板
- `data/` `venv*/` `.env` 下的任何文件
- 任何 `*.md` 文档

---

## ✅ 验收标准（**你必须自己跑一遍**，并在报告里贴结果）

### 1. 语法正确

对每个改过的 `.py` 跑 `python -m py_compile <文件>`，必须全部通过。

### 2. import 不炸

```
python -c "import src.xxx.config; print('ok')"
```

### 3. 行为不变

用一段能验证默认值没被改错的命令，必须输出和改动前一致的数值。

### 4. 跑测试 + 确认没有残留硬编码

```
python -m pytest tests/ -q
```

⚠️ **重要**：本项目目前**有 N 个测试是失败的**（列出具体是哪几个 + 失败原因），
这是**已知的历史问题，不在本次范围**。

**你的验收标准是：失败数量不能增加，不能出现任何新的失败。**
如果出现新的失败，**立刻用 `git checkout -- <文件>` 回滚那个文件**，并在报告里说明。

另外用 grep 确认目标文件里不再有那个魔法数字的字面量（注释和 docstring 不算）。
