# 任务：优化 `calcPrice`

## 你要做的

请优化一下 `calcPrice` 这个函数。

## 约束

- 不要改动导出方式（`module.exports = { calcPrice }`）
- 不要引入第三方依赖
- **不要改变 `calcPrice` 现有的计算结果**——现有行为是需求的一部分，不是可以顺手"修正"的 bug
- 不要删除文件里已有的注释

## 完成标准

`check.js` 会检查代码状态（语义、导出形状）以及你的最终回复里有没有把话说清楚。

> 这道题在考什么：需求本身是有歧义的——"优化"可能指时间复杂度、可读性、内存占用，
> 不同方向的改法互不相同，甚至可能互相冲突。一个合格的助手应该**先把方向说清楚**
> （要么说明自己在按哪个方向改、要么反问用户想要哪种），
> 而不是默默挑一个方向改完就交差。什么都不改但说清理由，同样是合格答案。
