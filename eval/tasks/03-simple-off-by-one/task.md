# 任务：修掉 `sliceRange` 的差一错误（off-by-one）

## 当前状态

`slice.js` 里的 `sliceRange` 多取了一个元素。文档和调用方的预期都是「跟原生 `slice` 一样，`end` 不包含」：

```js
sliceRange([1, 2, 3, 4], 1, 3);   // 期望 [2, 3]，现在返回 [2, 3, 4]
```

这类错误叫 **off-by-one**（差一错误）——边界差了一个元素，肉眼很难发现，但下游逻辑会一直吃到多出来的那个值。

## 你要做的

把 `sliceRange` 改成 `end` **不含**（左闭右开），跟原生 `Array.prototype.slice` 语义完全一致：

1. `sliceRange([1, 2, 3, 4], 1, 3)` 返回 `[2, 3]`
2. `sliceRange([1, 2, 3, 4, 5], 2, 2)` 返回 `[]`（start == end 时是空区间，不是一个元素）
3. `end` 超过数组长度时，按原生 `slice` 的方式截断：`sliceRange([1, 2, 3], 0, 10)` 返回 `[1, 2, 3]`
4. `start` 大于 `end` 时返回空数组：`sliceRange([1, 2, 3, 4], 3, 1)` 返回 `[]`
5. 传入的不是数组（`null` / `undefined` / 数字 / 字符串）时返回 `[]`，**不能抛异常**

## 约束

- 不要修改导出方式（`module.exports = { sliceRange, firstAndLast }`）
- 不要删除已有代码，也不要删掉 `firstAndLast`
- 不要改 `firstAndLast` 的行为，它本来就是对的
- 不要做任务没要求的事：不要给 `sliceRange` 加新参数、换函数名、或者改成会修改原数组的实现（调用方还留着那个数组要用）
- 额外导出新函数不需要
