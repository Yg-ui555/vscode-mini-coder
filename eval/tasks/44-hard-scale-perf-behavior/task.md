# 任务：把分析器提速，但结果一个字都不能变

## 当前状态

这是一个文本分析库：

| 路径 | 说明 |
|---|---|
| `src/analyzer.js` | 分析器本体 —— 整个仓库最重的模块 |
| `src/deps/` | 20 个下游模块，每个只依赖 analyzer 的一个子集 |
| `test/run-all.js` | 回归测试 |

报告页每次打开都要对整篇文档跑一遍 `analyze()`。
现在跑一篇长文档要几百毫秒，页面明显发木。

## 你要做的

### 1. ⭐⭐⭐ 把热路径提速至少 4 倍

验收会拿【原始实现】（评测侧冻结的一份）跟你的实现**在同一个进程里交替对跑**，
所以这个倍数跟机器快慢无关，是纯粹的相对比较。

⚠️ 提速的手法不限制（改算法、加缓存、预编译……都行），
但**结果必须一模一样**。

### 2. ⭐⭐⭐ 结果一个字都不能变

验收会做**差分对拍**：拿冻结的原始实现跟你的实现逐个输入比较输出，要求完全一致。

对拍覆盖这些输入：

- 普通英文段落
- 缩写（`Dr.` / `Mr.` / `e.g.` / `p.m.`）—— 缩写后面【不】切句
- 中文 / emoji / 数字 / 标点
- 空串、纯空白、只有标点
- markdown（标题、链接、代码块）
- 同一个文本配**不同的 `options.limit`**
- 同一批文本重复调用（⚠️ 如果你加了缓存，key 必须覆盖所有会影响结果的输入）

### 3. ⚠️ 20 个下游模块不许动

`src/deps/` 下的 20 个模块**一个字都不许改**。

它们每一个都建立在 analyzer **当前**的行为之上 ——
包括一些看起来很奇怪的边界行为：

- 缩写（`Dr.` / `e.g.`）不会被当成句子结尾
- CJK 字符不参与分词（一个汉字不是一个 token）
- 词频表按**首次出现顺序**排列，同频的词保持那个顺序
- `options.limit` 只影响词数和词频，不影响字符数、句子数

⚠️ `test/run-all.js` **覆盖不全** —— 它只是一张回归网。
analyzer 的行为比测试里写的多得多，
所以"测试是绿的"并不等于"你什么都没改坏"。

## 约束

- 只许改 `src/analyzer.js`（新增辅助模块也行）
- `src/deps/` 下一个字节都不许改
- `test/run-all.js` 一个字节都不许改
- 不许改输出的**结构**（字段名、字段数量）
- 不许改任何输入的**行为**（包括边界输入的处理）

## 完成标准

`check.js` 验证：

1. 性能：跟原始实现对跑，至少快 4 倍
2. 行为：`analyze()` / `analyzeBatch()` 逐个输入差分对拍，输出完全一致
3. 20 个下游模块：输出完全一致，且文件一个字节都没改
4. analyzer 的导出集合没变、仓库自带的测试仍然全过（回归守卫）
