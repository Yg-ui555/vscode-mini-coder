# 任务：对外 API 的字符串截断行为要统一

## 当前状态

这是一个分层的工具库，四层：

```
core  →  internal  →  public  →  api
```

每一层都转发下一层的符号。对外入口在 `src/api/` 下，分成几个分册：

| 入口 | 用途 |
|---|---|
| `src/api/index.js` | 主入口 |
| `src/api/http.js` | HTTP 分册 |
| `src/api/cli.js` | CLI 分册 |
| `src/api/feed.js` | feed 分册（给外部聚合方订阅） |

产品提了个需求：**对外的 `truncate` 必须是"按字符截断 + 一个省略号"**：

```js
truncate('hello world', 5)   // → 'hello…'
truncate('你好世界', 2)       // → '你好…'    ← 按字符，不是按字节
truncate('hi', 10)           // → 'hi'       ← 不超长就不截
```

现在 4 个入口里**只有一部分**是这个行为。另一部分还是老的字节级语义：
截断点按字节算（多字节字符会被切坏），省略号是三个点 `...`。

## 你要做的

让 4 个对外入口的 `truncate` **全部**符合上面写的规范。

## 你得先搞清楚的事

⚠️ **这个仓库是分层的，而且每一层都可能替换下一层的符号。**

"我改了 `core` 里的函数，为什么对外的行为一点没变"——
这种问题在这类仓库里非常常见，答案通常在中间某一层的转发文件里。

所以别只改一个地方就收工：**4 个入口的来源链各不相同**。

## 约束

- ⚠️ **只有对外入口的 `truncate` 要改。其他模块的对外行为一个字都不许变。**
  有几条内部老链路（日志摘要、预览条、徽标）依赖着现在的老截断语义，
  改坏了它们就是回归。
- 不许改 4 个入口里**其它**导出（`formatBytes` / `slugify` / `parseRange` / `clamp` …）的行为
- 不许删掉任何一层的转发关系
- 不许删掉任何导出

## 完成标准

`check.js` 会验证：

1. 4 个入口的 `truncate` 都符合规范（ASCII / 中文 / 不超长 三种输入）
2. ⭐ 4 个入口的 `truncate` 行为**完全一致**
3. ⭐⭐⭐ 依赖老截断语义的那几条内部链路，输出**一个字节都没变**
4. 4 个入口的其它导出没变（回归守卫）
5. 4 个入口的关键导出都还在（回归守卫）
