# 任务：给用户格式化加一个"紧凑样式"，并且把旧写法彻底废掉

## 当前状态

这是一个两包仓库：

| 包 | 路径 | 说明 |
|---|---|---|
| `@wxu/core` | `packages/core/` | 通用能力：用户、订单、账单、工具 |
| `@wxu/app` | `packages/app/` | 应用层：页面、报表、后台任务 |

`packages/core/src/user/format.js` 里的 `formatUser` 是全仓库的用户渲染入口。

⚠️ 现在有一个**静默**的问题：

`app` 包里有一批调用点**已经在传第二个参数**了（`'compact'` / `'full'`），
但 `formatUser` 一直**忽略**第二个参数 —— 所以那些调用点渲染出来的
全是完整样式。调用方以为自己在用紧凑样式，实际拿到的不是，
**而且从头到尾没有任何报错**。

## 你要做的

### 1. ⭐⭐ core：给 `formatUser` 加一个样式选项

新签名：

```js
formatUser(user, options)
```

| 情况 | 结果 |
|---|---|
| `options = { style: 'full' }` | `Ada (36岁)`（跟现在的输出一致） |
| `options = { style: 'compact' }` | `Ada(36)` |
| `options` 不是对象（字符串 / 数组 / 不传） | **抛 TypeError** |
| `options.style` 不是 `'full'` / `'compact'` | **抛 TypeError** |

⚠️ **为什么必须抛错、而不是"容错处理"**：

> 旧的字符串写法之所以能悄无声息地错这么久，就是因为它**不报错**。
> 我们要让这一类错误**立刻炸出来**，而不是继续静默地渲染错。
>
> 所以：**传旧写法必须报错**，不能"顺手兼容一下"。

报错信息里要说明是参数不对（让人一眼看出该怎么改）。

### 2. ⭐⭐⭐ app：把所有调用点迁到新写法

`app` 包里**所有**调用 `formatUser` 的地方，都要改成传对象。

⚠️ 有几个地方不是一眼能看出来的：

- 有的地方**一个参数都没传**（只是碰巧能跑）
- 有的地方参数是**转发**出去的 —— 看调用点看不出来，得顺着函数体读
- `core` 包内部还有别的函数调用了 `formatUser`（比如一个已废弃的别名），
  它们也得跟着改，否则会直接抛错

## 约束

- 不许改 `app` 包里**其它**导出的行为
  （`formatUserId` / `formatUserTag` / `searchUsers` … 名字长得像，但不是一回事）
- 不许改 `app` 包现有导出函数的**签名**
- 不许改 `core` 包里 `formatUser` 以外的函数的行为
- 不许删任何导出

## 完成标准

`check.js` 验证：

1. core 的 `formatUser` 支持两种样式
2. ⭐ core 的 `formatUser` 对旧写法（字符串 / 不传 / 未知 style）**抛 TypeError**
3. ⭐⭐⭐ app 各目录的调用点**全部**迁到了新写法（逐个模块验输出）
4. core / app 其它导出的行为没变（回归守卫）
