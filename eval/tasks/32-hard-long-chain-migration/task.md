/**
 * 任务：把 `readConfig` 迁移到新的异步 API
 *
 * ## 当前状态
 *
 * 这个项目里有一个同步的配置读取函数 `readConfig`，被**五个模块**调用，
 * 还有**四个测试文件**覆盖它。
 *
 * 现在产品那边要求改成异步（因为配置要从网络拉取）。
 *
 * ## 你要做的
 *
 * ### 1. ⭐ 把 `readConfig` 改成异步
 *
 * 新签名（题目明确要求用 `async` 关键字声明）：
 *
 * ```js
 * async function readConfig(path)  →  返回 Promise<config>
 * ```
 *
 * ⚠️ 关键：**所有调用方都要改成 `await`**。
 * 这是本题的核心 —— 改一个基础函数，看你能不能把所有影响面都找出来。
 *
 * ### 2. ⭐ 找出并修改所有调用方
 *
 * 项目里有**五个**模块调用了 `readConfig`。
 *
 * ⚠️ **不是每个都容易找到**，这正是本题要考的东西：
 *   · 有的在**回调函数**里被调用（HTTP 的 listen 回调、定时器回调）
 *   · 有的通过**动态 require**（字符串拼出来的路径）拿到的
 *   · 有一个调用点**藏在重新导出后面** —— 它拿到的不是源模块，而是
 *     中间层 re-export 出来的那个函数。所以"grep 谁 require 了源文件"是**不够**的，
 *     你得 grep **函数名本身**。
 *
 * 请用 grep / glob 工具**自己找出来**，不要靠猜，也不要只看 import 语句。
 *
 * ⚠️ 找到之后，别急着改 —— 先想清楚每个调用点的**形状**不一样：
 *   · 普通函数体里的直接调用 → 直接 `await` 就行
 *   · 回调函数里的调用 → 回调本身不是 async，要么用 `.then()`，要么把回调改成 async
 *   · 模块顶层的调用 → CommonJS 没有顶层 await，必须包一层
 *
 * ### 3. ⭐ 修掉因此产生的所有连锁问题
 *
 * 因为 `readConfig` 变成 async 了，几个地方会出新问题：
 *   · CLI 的顶层调用要包一层，**并且要处理好 rejection**
 *     （否则进程会以非 0 退出码结束，CI 会红）
 *   · 回调里的调用要改成 `.then()` 或者把回调改成 async
 *
 * ### 4. ⭐ 确认四个测试文件仍然全绿
 *
 * 测试文件里**大概率一个字都不用改**（它们本来就用了 `await`，
 * 而 `await` 对同步值和 Promise 都成立）。
 *
 * 但你必须**确认**它们还能跑通，并且：
 *
 * ⚠️ **测试文件可以改** —— 但**只能改异步等待方式**，
 * 不能改断言的期望值（除非期望值本身依赖了同步行为），
 * 也不能删测试、不能加 `skip` / `only`。
 *
 * ## 约束
 *
 * - **不要改 `readConfig` 的配置解析逻辑**（读哪些字段、默认值是什么，一个都不能变）
 * - **不要删任何调用方**（哪怕你觉得某个调用方多余）
 * - **不要改任何公共函数的签名** ——
 *   `startServer` 仍然要**同步返回 server 对象**，
 *   `processTask` / `bootstrap` 仍然要用**回调**交付结果。
 *   现有调用方（包括测试）依赖这些形状，改了就等于改了公共 API。
 * - **不要改测试的断言期望值**
 * - `readConfig` 仍然要从 `src/config.js` 导出
 *
 * ## 完成标准
 *
 * check.js 验证：
 * 1. `readConfig` 是 async 函数，且返回 Promise
 * 2. **五个调用方全部改成了正确的异步等待方式**
 * 3. 四个测试文件全部适配，且断言期望值没被改
 * 4. 配置解析逻辑没变（返回值一模一样）
 * 5. `node test/run-all.js` 全部通过
 * 6. `node src/cli.js` 能正常跑完并输出正确内容（退出码 0）
 *
 * 最后两条最重要 —— **这是唯一能证明你改对了的方式**。
 *
 * ⚠️ 提醒：只把 `readConfig` 改成 async 是**不够**的。
 * 漏改任何一处调用方，原本绿的测试就会红 ——
 * 而这正是这个题目真正想测的能力。
