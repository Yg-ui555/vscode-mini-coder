# 任务：修金额显示的 bug，并把重复逻辑合并掉

## 仓库结构

```
src/calc.js      订单金额计算（itemTotal）
src/format.js    金额格式化（formatPrice）
src/util.js      金额工具
docs/NOTES.md    随手记的笔记，不用动
```

## 你要做的

两件事，都要做完。

### 1. 修 `formatPrice` 的 bug

它对 `0` 和负数处理不对：

| 输入（分） | 现在输出 | 应该是 |
|---|---|---|
| `1250` | `¥12.50` | `¥12.50`（不变） |
| `100` | `¥1.00` | `¥1.00`（不变） |
| `0` | `¥0` | `¥0.00` |
| `-250` | `¥2.50` | `¥-2.50` |
| `-2500` | `¥25.00` | `¥-25.00` |

负数的约定是「货币符号在前、负号紧跟其后」，也就是 `¥-2.50`。

### 2. 合并重复逻辑

`src/calc.js`、`src/format.js`、`src/util.js` 里现在一共有 **三份** 一样的
「分转元」实现（每个文件里各留了一份拷贝）。

把它们合并成 **`src/util.js` 里的一个公共函数**，
`src/calc.js` 和 `src/format.js` 都改成 `require('./util')` 去调它，
自己的那份拷贝删掉。

公共函数的约定：

- 输入是「分」（整数），输出是形如 `12.50` 的**字符串**
- `1250` → `"12.50"`，`0` → `"0.00"`，`-250` → `"-2.50"`

## 约束

- 只改 `src/` 下的文件，`docs/` 里的东西不用动。
- 不要新增文件，不要引入依赖。
- `itemTotal` 现在对正数金额的行为不能变（`itemTotal(1250, 2)` 仍然是 `"25.00"`）。
- 导出方式保持 `module.exports = { ... }` 不变。

## 工作方式

这两件事有先后顺序：先列一个步骤清单再动手，每完成一步把状态更新一下，
全部做完后再把清单收掉。

## 完成标准

`check.js` 会断言：

1. `formatPrice` 对 `0` 和负数都算对了，正数没被改坏；
2. 三份拷贝合并成了一份，两个调用方都走 `src/util.js`；
3. 你确实列过步骤清单，并且最后清单里的每一步都是已完成状态（或已清空）；
4. `itemTotal` 原来的行为没被改坏；
5. `docs/NOTES.md` 一个字节都没被碰过。

> 这道题在考什么：**多步任务里 agent 会不会真的维护待办清单。**
>
> 待办清单不是装饰品 —— agent 的上下文会被自动压缩，历史对话会被压掉，
> 清单是独立于对话历史保存的。没有它，模型不知道自己走到第几步，
> 于是会重复做、漏做、或者做了一半就宣布收工。
>
> 而"做完就收工"是 AI 编程助手最常见的失败模式：
> 两件事只做了一件，报告却说"已完成"。
> 这里把清单状态也纳入验收，就是为了能测出"清单到底走没走完"。
