# 任务：修掉 `dedupeBy` 把「缺字段的项」吞掉的 bug

## 当前状态

`dedupe.js` 里的 `dedupeBy` 拿 `keyFn(item)` 的返回值当去重 key。问题是真实数据里经常有**缺字段**的对象——字段不存在时 `keyFn` 返回 `undefined`，于是这些互不相干的对象全被当成同一个 key，后面的全被丢掉：

```js
dedupeBy([{ name: 'a' }, { name: 'b' }, { name: 'a' }], (x) => x.id);
// 现在返回 1 项（只剩 { name: 'a' }），期望 3 项
```

## 你要做的

**语义约定（按这个来，不用自己发挥）：**

- `keyFn(item)` 返回 `undefined` 时，**改用元素本身当 key**
  - 对象按**引用**区分：不同的对象引用算不同的 key，都保留
  - 原始值（数字 / 字符串 / 布尔）按**值**区分：`[1, 1, 2]` 在 key 全是 `undefined` 时应保留 `[1, 2]`
- `keyFn(item)` 返回 `null`、空字符串、`0` 这些「有值但看起来像空」的结果时，**照常当有效 key 使用**——只有 `undefined` 才回退
- 保留首次出现的顺序不变，返回新数组，不修改入参

例子：

```js
dedupeBy([{ name: 'a' }, { name: 'b' }, { name: 'c' }], (x) => x.id);
// 应返回 3 项（key 全是 undefined，不能因为都是 undefined 就只留一个）

dedupeBy([{ id: 1 }, { name: 'x' }, { id: 1 }, { name: 'y' }], (x) => x.id);
// 应返回 3 项：{ id: 1 } 去重留一个，两个缺 id 的对象都留下
```

另外补一条健壮性：传入的不是数组（`null` / `undefined` / 数字）时返回 `[]`，不能抛异常。

## 约束

- 不要修改导出方式（`module.exports = { dedupeBy, countBy }`）
- 不要删除已有代码，也不要删掉 `countBy`
- 不要改 `countBy` 的行为——它没有这个 bug，本次任务不要求动它
- 不要做任务没要求的事：不要换函数名、不要改参数顺序、不要新导出函数
- 不要用「给每个元素编个递增下标当下标」这种写法绕过问题，那会让同一个对象重复出现时也被当成两项
