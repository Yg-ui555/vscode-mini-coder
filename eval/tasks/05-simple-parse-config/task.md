# 任务：让 `parseConfig` 支持注释行

## 当前状态

`config.js` 能解析 `key = value`，但不支持注释。所以配置文件里**被注释掉的旧配置**会被当成真配置读进来：

```js
parseConfig('# port = 3306\nport = 8080');
// 现在返回 { '# port': '3306', port: '8080' }，期望 { port: '8080' }
```

## 你要做的

1. **整行注释**：行首（去掉缩进之后）以 `#` 开头的行，整行跳过，不进结果
   - `   # port = 3306` 这种前面带空格的也算注释（先 trim 再判断）
   - 注释行可以带 `=`，也可以不带
2. **不要误伤值里的 `#`**：只有整行开头是 `#` 才算注释
   - `color = #ff0000` 应解析成 `{ color: '#ff0000' }`，`#ff0000` 是值的一部分
3. **保持已有的正确行为**（这几条现在是对的，别改坏）：
   - 值里有 `=` 时只按**第一个** `=` 分割：`cmd = a=b=c` → `{ cmd: 'a=b=c' }`
   - 空行 / 只有空白的行跳过
   - 没有 `=` 的行跳过：`just a note` 不会产生任何 key
   - key 和 value 两边都要 trim
4. **健壮性**：传入的不是字符串（`null` / `undefined` / 数字）时返回 `{}`，不能抛异常

## 约束

- 不要修改导出方式（`module.exports = { parseConfig, getConfigValue }`）
- 不要删除已有代码，也不要删掉 `getConfigValue`
- 不要改 `getConfigValue` 的默认值机制：key 存在就返回它的值（哪怕值是空字符串），不存在才返回 `defaultValue`
- 不要做任务没要求的事：不要顺手加行尾注释（`port = 8080 # 生产`）、不要把值转成数字 / 布尔、不要新导出函数
- 不要动 `01-simple-username-validate` 或沙箱里其他文件
